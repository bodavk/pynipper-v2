## [Unreleased]

### Fixed

- FortiOS exports with quoted values that span several lines (PEM private keys, certificates, comments, replacement messages) no longer fail with "Invalid quoting". The parser joins the lines into one statement, redacts secrets, evaluates multi-line public certificates, and keeps later line numbers exact. An unclosed value is still a controlled parse error reported at its first line (PT-002).
- Checked the other families for the same class of defect (PT-003). Junos display-set exports with a multi-line quoted value were misdetected as hierarchical and silently produced no findings; ScreenOS, AOS-S and SonicOS read quoted banner text as commands; IOS/IOS-XE delimited banners and EOS `banner ... EOF` bodies were scanned as commands and could create false findings. All now group or mask these values. ASA, F5 TMOS, PAN-OS XML and Check Point were unaffected. A shared `src/devices/common/source_lines.py` helper provides the grouping.
- Cisco IOS/IOS-XE/EOS and ASA evidence line numbers no longer shift after blank lines, which CiscoConfParse used to drop.
- Pinned `MarkupSafe>=2.0,<2.1`: Jinja2 2.11.3 fails to import with MarkupSafe 2.1+, so fresh installs could not generate reports (PT-001; long-term upgrade tracked as PT-008).

### Changed

- Findings now cite the configuration line behind each evidence entry (PT-004). Plugins pass parser `ConfigEvidence`; HTML shows `Line N (file)` and JSON adds `evidence_locations` with `line`, `source` and `line_origin` next to the unchanged `evidence` strings. Plain evidence text is located only when it equals exactly one input line; absence statements, summaries and redacted or repeated text keep no line. PAN-OS XML elements and Check Point rules/objects now carry their start line.
- Junos SRX now resolves active zone-to-screen bindings and reports explicitly deactivated TCP SYN-flood, UDP-flood or ICMP-flood options only when the zone contains an auditor-classified external interface. Active UDP/ICMP-flood screens with explicit `alarm-without-drop` are reported separately. Unbound screens, omitted options, unresolved group inheritance and non-SRX models remain ungraded.
- PAN-OS attached zone-protection profiles now report an explicit reconnaissance `scan` action of `allow` on an auditor-declared external zone. Vendor-supported alert-only actions are left ungraded; a possible DoS flood rule does not hide a scan-allow action.
- F5 BIG-IP active LDAP/certificate-LDAP checks now distinguish protected transport from TLS peer validation and report explicit `ssl-check-peer disabled` only when every configured provider uses SSL/StartTLS with peer checking disabled. Missing or verified alternatives suppress this bounded finding.
- Added a bounded F5 BIG-IP administrative LDAP transport check: an explicitly active LDAP or certificate-LDAP source with configured servers is reported when every exported same-type provider explicitly disables SSL/TLS. Unknown, SSL-enabled or StartTLS provider alternatives do not trigger; network-path protection remains outside the saved export.
- F5 BIG-IP now reports an explicitly selected remote authentication source when every exported same-type provider object has `servers none`. RADIUS, LDAP, TACACS+ and certificate-LDAP profiles are modeled separately, with last-setting precedence and secret-free evidence; absent providers, fallback policy and effective roles remain unresolved.
- Began PAN-OS zone-protection coverage with a typed device/vsys zone-to-profile binding and explicit disabled-SYN/UDP/ICMP-flood findings only for zones containing an auditor-declared external interface. Potential DoS-policy alternatives, unmerged Panorama inheritance, unresolved profiles and missing/default settings remain ungraded.
- Extended opt-in secret-report evidence to SonicOS 7 E-CLI built-in and resolved local administrator passwords, excluding removed/replaced directives, unrelated users and ambiguous repeated administration sections. The input snapshot is verified before unmasking; normal findings remain redacted.
- FortiOS IPS analysis now identifies explicit source/destination IP exemptions on the first broad, enabled high/critical blocking selector used by an active accept policy. The check honors selector order and ignores disabled, lower-severity, and severity-unknown cases; signature-ID severity and vendor defaults remain ungraded.
- Extended basic F5 TMOS password-policy analysis with a vendor-documented explicit zero-login-failures lockout finding and a zero minimum-length finding gated to enabled policy enforcement. Added a separate finding for explicit plaintext `auth user password` while keeping values out of normal reports; masked and encrypted-password forms are not graded as plaintext. Ordered overrides, malformed values, public HTML/JSON redaction, and the permanent vulnerable corpus are tested; F5 role/AAA coverage remains open.
- Added a CLI-only `--show-secrets` opt-in that places parser-qualified unmasked credential source lines in a separate HTML/JSON appendix for IOS/IOS-XE/ASA, FortiOS, Junos, ScreenOS, AOS-S, EOS, and F5 TMOS. Default findings and inventory remain redacted; unsupported families are rejected. Sensitive reports warn the operator and require exclusive creation at a new output path. All CLI reports now refuse to overwrite their input configuration. Broader secret-type and device coverage remains open.
- Simplified CLI device selection with one recommended short name per configuration family while retaining historical IDs and aliases. Omitting `-d` now conservatively identifies distinctive exports; ambiguous IOS/IOS-XE or unrecognized inputs require an explicit family. The resolved canonical family is recorded in reports, with fixture and CLI tests for detection and safe failure.
- Added an opt-in ASA WebVPN client-certificate policy check. It resolves enabled listeners, selectable remote-access group URLs and explicit authentication modes, reporting only a proven AAA-only configured path under the approved certificate requirement. URLs are redacted; SAML and unexported MFA remain unknown.
- Added opt-in ASA IKE DH policy assessment for explicitly enabled IKEv1/IKEv2 families. An exact approved group list flags non-legacy negotiable alternatives outside the selected profile without ranking finite-field and elliptic-curve group numbers or duplicating existing legacy-group findings.
- Added selected-trustpoint IOS/XE HTTPS public-certificate assessment. When the server is explicitly active and its selected chain contains one exported identity certificate, the shared evaluator checks weak public algorithms and optional assessment-time validity, expected identity and approved anchor trust. Unselected or absent material is ungraded, and neither certificate payloads nor private keys enter findings.
- Added a bounded IOS/XE routing key-lifetime check for active OSPF, RIPv2 and EIGRP key-chain bindings. With an explicit audit timestamp and UTC-zero device clock, it reports only chains proven unable to send or accept with any material-bearing key; rollover keys, default-forever lifetimes and unsupported clock/syntax cases are handled conservatively. Secret values are excluded from evidence.
- Added an assessment-gated IOS/XE boot-configuration check: on a device explicitly marked commissioned, a qualified saved export with an active TFTP boot host/network fetch is reported. Ordered removals are honored; endpoints and paths are redacted. CNS/PnP and ambiguous release/default behavior remain ungraded.
- Added bounded Cisco IOS/XE external-BGP IPv4 filter checks. The parser retains effective directional neighbor/peer-group policy references and recognizes a standalone prefix list whose sole rule permits every IPv4 route, a sole empty permit route-map sequence, or a sole universal-permit AS-path filter list; absent referenced definitions are distinguished from unrestricted policies. Other attached policy types suppress a permit-all conclusion, and complex/unknown syntax is not treated as proof of unrestricted exchange.
- Extended the Cisco stage of SC-005 with bounded classic default-VRF IPv4 EIGRP authentication alongside RIPv2. EIGRP network selectors are bound to active interface addresses and per-AS MD5 mode/key-chain settings; findings distinguish missing authentication from unresolved key material. Passive EIGRP interfaces are excluded because they do not form adjacencies, unlike passive RIP interfaces, which still receive updates. Named/address-family EIGRP, VRF routing, key lifetimes and operational peers remain ungraded. Key material is redacted at the parser boundary.
- Started the Cisco stage of SC-005 with bounded classic IPv4 RIPv2 authentication. The parser now binds active default-VRF RIP networks to interface addresses and resolves ordered per-interface receive-version, key-chain and text/MD5 mode state. Findings distinguish no key binding, unresolved exported keys, cleartext authentication and explicit RIP v1 reception; passive interfaces remain assessed for inbound updates. Named/VRF RIP, unknown receive-version behavior, key lifetimes and operational peers remain ungraded. Key material is redacted at the parser boundary.
- Added bounded SC-004 IOS/IOS-XE BPDU-guard analysis for explicitly assessed access edges. Ordered global PortFast/guard defaults and local guard overrides now distinguish proven disabled protection from unknown omissions; global guard counts only with effective PortFast. Explicit local BPDU filtering with configured guard is a separate bypass finding. Trunks, LAG members, shut ports and unknown roles are not graded. Added public CLI, override and redaction tests.
- Began SC-003 with bounded IOS/IOS-XE access-admission checks. On an active switchport explicitly classified as an access edge, ordered parser state now reports explicit `force-authorized`, active open authentication, or an explicit global 802.1X disable overriding an `auto` port. The parser retains the global AAA declaration separately; omitted defaults, backend reachability, fallback/guest policy, inactive ports and other device families remain ungraded.
- Completed the bounded AOS-S portion of SC-012: effective remote syslog state now accounts for server removal, `no debug destination logging`, and Event Log forwarding. On verified 16.10/16.11 exports, an explicit `logging severity major` with an active server reports exclusion of error-severity events; `no debug event` is a separate finding. Severity resets, unknown values, inactive destinations and unsupported releases are not promoted to severity conclusions.
- Extended bounded SC-012 coverage to Arista EOS. Ordered `logging trap`/`logging buffered` settings now report explicit thresholds below syslog level 3, which exclude even error-severity events from configured remote hosts or the local buffer respectively. Remote hosts include VRF-scoped bindings; explicit `no logging on`, resets, conflicts and malformed levels are kept distinct from active threshold conclusions. More inclusive security-event ranges remain policy-dependent.
- Added bounded SC-012 FortiOS remote-syslog transport assessment. Enabled syslog destinations with explicit `enc-algorithm disable` are reported as cleartext even when TCP delivery is reliable; explicitly low encryption or obsolete minimum TLS versions are reported separately. Disabled/unconfigured sinks, omitted encryption state, conflicting transport settings and inactive VDOM overrides remain ungraded. Added direct/VDOM, multi-sink and public-report tests.
- Extended bounded SC-009 coverage to FortiOS IPS sensors. For active accept policies with an attached custom sensor, ordered, explicitly enabled broad high/critical filters set to pass/monitor now produce a finding even when another filter blocks. Unset status/action, narrowed signature attributes, built-in sensors and FortiGuard signature defaults remain ungraded; required inspection-function policy and exception handling are still open.
- Added bounded SC-009 PAN-OS threat-profile action analysis. Attached anti-spyware and vulnerability profiles now retain ordered severity selectors and report an explicit first broad critical/high `allow` or `alert` even when another selector blocks; earlier broad blocking or unresolved selectors, narrow predicates, unbound profiles, built-ins, and unknown signature exceptions are not promoted to effectiveness claims. FortiOS action/default qualification and policy-selected required profile types remain open.
- Added bounded SC-002 ASA/EOS administrative-policy coverage. ASA reports explicit local-login lockout reset on supported releases, a locally applicable password minimum below Cisco's eight-character recommendation, and active SSH/ASDM idle settings above the existing ten-minute project target; newer HTTP connection timeout takes precedence and multi-context/older unsupported settings remain ungraded. EOS reports an explicitly disabled or one-character global local-password minimum only on qualified releases with a local administrative login path; named profiles and STIG-specific thresholds remain unknown pending profile qualification.
- IOS/IOS-XE VTY AAA now overlays overlapping line ranges and resolves effective authentication, EXEC/privilege-15 authorization, accounting list bindings, and named server-group membership. Explicit `none`/`if-authenticated` authorization bypasses, unbound or disabled accounting, and undefined/empty bound server groups receive distinct findings; local fallback and external server reachability remain separate.
- Added explicit PAN-OS interzone-default allow-override detection with local-vsys precedence over shared definitions; unmerged Panorama inheritance and malformed actions remain ungraded (SC-007). FortiOS now resolves custom administrator access-profile write permissions and applies existing privileged-account trust-host and MFA checks to bound write-capable roles without treating unresolved profiles as read-only (bounded SC-011).
- Added basic F5 BIG-IP TMOS support for saved tmsh/SCF text exports. The registered parser and explicit plugin pipeline assess configured SSH and web management source restrictions, session timeouts, CLI auditing, local password-policy enforcement, standard remote syslog, and enabled virtual servers with attached Client SSL profiles that explicitly permit non-SSL traffic. Malformed or unrelated input produces a redacted parse-error report; omitted and unresolved settings remain ungraded. Added paired corpus, public CLI, parser, and redaction coverage, plus support and architecture documentation.
- Junos SRX now audits an explicit global `permit-all` default security policy as unmatched transit traffic and includes that fallback in normalized policy coverage (RV-011). IOS/IOS-XE and EOS now classify additional effective RADIUS, line-password, and literal TerminAttr secret storage with redacted evidence (RV-006); IOS also reports exact known-default plaintext enable/line values and effective default SNMP communities separately from generic storage/protocol findings (RV-007). ScreenOS VPN anti-replay (RV-008) remains evidence-gated pending a release-specific vendor command reference.
- EOS NTP now reports explicit server associations lacking both a key binding and NTS profile even when the export omits the software release (RV-005). Incomplete key and SSL-profile options remain unknown; configured key references with unknown global authentication remain ungraded. Added VRF, removal, malformed-input, redaction, and public CLI coverage.
- Real-world validation follow-up: IOS/IOS-XE now overlays effective line ranges and reports explicit active console/AUX/TTY/VTY idle timeouts above ten minutes while preserving disabled, reset, malformed, and unknown states (RV-004); ASA WebVPN requires a resolved interface attachment before evaluating explicit inbound SSL protocol and cipher policy, reporting obsolete versions and weak suites separately (RV-001); unrendered PAN-OS/FortiOS deployment templates carry incomplete-input coverage and suppress absence-only findings while retaining explicit risks (RV-009); PAN-OS management complexity and effective system syslog forwarding resolve their actual XML hierarchy and profile bindings (RV-003); ASA weak IPsec transform findings require an interface-attached static/dynamic crypto-map binding, with unresolved active references reported separately (RV-002).
