# Device parsers

The authoritative device list is `src/devices/registry.py`. Every registered parser implements `BaseDeviceParser` and returns both its native representation and a `NormalizedConfig` snapshot with explicit knowledge state.

## Parser maturity

| Device ID | Parser | Current parser scope |
|---|---|---|
| `IOS_SWITCH`, `IOS_ROUTER`, `IOS_CATALYST` | `CiscoIOSParser` | Verified IOS-family parsing for HTTP/SSH and baseline controls, including effective typed management lines, AAA method/binding resolution, SNMPv3 user/group/view/ACL relationships, per-association NTP key/trust state, BGP peer-group/AF/VRF routing trust, explicit-interface OSPFv2 authentication, effective CDP/LLDP interface directions, explicit SSH-suite/key metadata, and secret-free credential formats |
| `IOS_XE` | `CiscoIOSXEParser` | Verified IOS composition, including management-line/AAA/SSH state and typed access-edge VLAN/snooping/DAI/source-guard/port-security relationships, plus explicitly scoped or configured IOS-XE MACsec and active crypto references |
| `ASA`, `PIX` | `CiscoASAParser` | Verified typed ASA management services, protocol-specific AAA bindings, session/SSH state, effective management SSL trustpoint-to-identity-chain attachment and public X.509 assessment, per-server NTP key/trust/algorithm state, ACL, logging, secret-free credentials, and SNMPv3 user/group/host-scope relationships; PIX shares parsing infrastructure but remains unqualified for current ASA 9.x defaults |
| `FORTIOS` | `FortiOSParser` | Verified grammar-aware CLI parsing with VDOM/global scope, mutation ordering, secret-redacted evidence, FortiOS 7.4+ typed RADIUS transport/profile-to-admin bindings, active UTM policy-to-group/member resolution, distinct IPv4/IPv6 local-in records, and same-VDOM active IPsec reference chains |
| `JUNOS` | `JunOSParser` | Verified hierarchical and display-set parsing, including effective services, credential formats, distinct stateless filters and SRX zone-pair policies, static address/application resolution, attached/interface-bound VPN reference chains, logging, crypto, BGP group/key-chain/AF/routing-instance trust, OSPFv2 interface authentication, and LLDP all-interface inheritance/disablement |
| `SCREENOS` | `JuniperScreenOSParser` | Verified ordered set/unset parsing for management, users and conservative credential/default metadata, objects, policies, logging, and crypto; ScreenOS 6.3 adds typed unmatched-policy state and independent active console/WebUI/auth-server timeout relationships, including policy-context bindings |
| `CHECKPOINT_FW1` | `CheckPointFW1Parser` | Verified S-expression parsing with typed ordered layers, rules, network/service objects, nested groups, negation, VPN/install/track/time context, legacy anonymous-name support, and bounded static address/protocol/port semantic resolution |
| `PAN_OS` | `PaloAltoPANOSParser` | PAN-OS XML device/vsys interfaces, attached management profiles, dedicated MGT state, ordered rules, same-vsys/shared security profile groups/members and action state, log references, administrators, password policy, DNS, typed primary/secondary NTP authentication, per-user SNMPv3 state, management SSL/TLS certificate assessment, content schedules, system-log forwarding, version, and explicit unknown Panorama inheritance |
| `HP_PROCURVE` | `HPProCurveParser` | ArubaOS-Switch running configuration with ordered services, users, per-user SNMPv3 algorithms/key state and communities, SSH suites, authorized managers, AAA/accounting, password control, VLAN/DHCP-snooping, per-port VLAN/trust/ARP/source-lockdown/port-security relationships, syslog, typed SNTP key/trust associations, version, and model; service defaults remain limited to 16.10 and new Layer-2 records to 16.10/16.11 |
| `SONICOS` | `SonicOSParser` | SonicOS 7 E-CLI `show current-config custom` only; typed interfaces, management, access rules, VPN proposals, per-user SNMPv3 algorithms/key state, syslog, authenticated NTP, and explicit security-service/dependency state; incompatible formats fail explicitly |
| `ARISTA_EOS` | `AristaEOSParser` | EOS metadata plus active eAPI HTTP/HTTPS, shutdown, VRF and service-ACL scope, effective local users and credential formats, AAA/exec authorization, explicit management SSH policy, SNMPv3 user/group/view/VRF-ACL relationships, syslog, and per-VRF symmetric/NTS time associations |

Registered aliases are resolved centrally. Additions must include registry, parser-contract, analyzer-dispatch, and alias tests.

The permanent corpus includes 32 inputs across eleven public pipelines. Its paired and edge-case PAN-OS, ArubaOS-Switch, SonicOS, and Arista EOS configurations cover unknown defaults, inactive APIs and objects, format rejection, scope isolation, reference resolution, ordered negation, and Wave 7 advanced state.

See [`docs/ARCHITECTURE.md`](../../docs/ARCHITECTURE.md) for parser responsibilities and [`docs/EXTENDING.md`](../../docs/EXTENDING.md) before adding a device or input dialect.
