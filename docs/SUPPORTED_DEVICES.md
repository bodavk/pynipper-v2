The canonical IDs and accepted aliases are defined in `src/devices/registry.py`.

For Junos, identified SRX models also receive an applied-IDP check: an IDP policy applied by an active permit rule whose every IPS rule is explicitly non-blocking (for example `no-action`) is reported. Identified SRX models also receive bounded external-zone screen analysis: an actively bound screen with explicitly deactivated SYN/UDP/ICMP flood protection, or active UDP/ICMP flood protection configured to alarm without dropping, can be reported. An auditor-supplied external interface role is required. This does not assess missing screen profiles, unexpanded groups, IDP effectiveness or operational protection.

For interactive use, the CLI recommends short family names such as `cisco-ios`, `cisco-ios-xe`, `cisco-asa` and `fortios`; historical IDs and aliases remain accepted. Omitting `-d` requests conservative format identification from distinctive export markers. Ambiguous Cisco IOS/IOS-XE exports and formats without a reliable marker require explicit `-d`; automatic identification does not infer switch/router or interface roles. The selected canonical family appears in the report's device type.

Thirteen public pipelines are continuously checked by `scripts/run_full_regression.py`. Its 39 permanent inputs include a FortiOS multi-line-value case and paired and syntax-variant F5 BIG-IP and Check Point Gaia basic-support examples. Registry reachability and expanded-baseline status do not imply universal vendor-version or full target-baseline parity. Static exports plus explicit assessment context can establish bounded certificate-material or on-box backup configuration state, but cannot prove the certificate currently served, revocation, backup transfer/retention/integrity/recovery, active subscription/licensing state, runtime inspection, installed effective policy, negotiated VPN security associations, peer identity, or whether a software release is currently supported.

## What `--show-secrets` shows

`--show-secrets` adds a separate, unmasked appendix of source lines for parser-qualified credentials. It never unmasks normal finding evidence and does not guarantee that every secret in an export was found. It is available for every family except Check Point Firewall-1 policy exports.

| Family | Lines shown |
|---|---|
| Cisco IOS / IOS-XE | Local credentials, effective SNMP communities and v3 keys, NTP keys, bound BGP/OSPF/RIP/EIGRP keys, TACACS+ keys, IKE pre-shared keys |
| Cisco ASA / PIX | Local credentials, SNMP communities and v3 keys, NTP keys, tunnel-group pre-shared keys, AAA server keys |
| Arista EOS | Local credentials, SNMP communities and v3 keys, NTP keys, bound routing keys, TACACS+ keys, IKE pre-shared keys |
| FortiOS | Current configured secret fields |
| Junos | Active RADIUS/TACACS+ secrets, NTP keys, SNMP communities and v3 keys, IKE pre-shared keys, routing authentication keys |
| ScreenOS | Administrator credentials, SNMP communities, auth-server secrets, IKE gateway pre-shared keys, NTP keys |
| SonicOS 7 | Built-in/local administrator passwords, RADIUS/TACACS+/LDAP secrets, SNMP communities, VPN shared secrets |
| HP ProCurve / ArubaOS-Switch | Manager/operator credentials, SNMP communities, SNMPv3 user keys, SNTP keys, RADIUS/TACACS+ keys |
| PAN-OS | Secret XML elements only |
| F5 BIG-IP | `auth user` password lines |
| Check Point Gaia | User password hashes, SNMP communities, SNMPv3 users |
