The canonical IDs and accepted aliases are defined in `src/devices/registry.py`.

For interactive use, the CLI recommends short family names such as `cisco-ios`, `cisco-ios-xe`, `cisco-asa` and `fortios`; historical IDs and aliases remain accepted. Omitting `-d` requests conservative format identification from distinctive export markers. Ambiguous Cisco IOS/IOS-XE exports and formats without a reliable marker require explicit `-d`; automatic identification does not infer switch/router or interface roles. The selected canonical family appears in the report's device type.

Twelve public pipelines are continuously checked by `scripts/run_full_regression.py`. Its 35 permanent inputs include paired and syntax-variant F5 BIG-IP basic-support examples. Registry reachability and expanded-baseline status do not imply universal vendor-version or full target-baseline parity. Static exports plus explicit assessment context can establish bounded certificate-material or on-box backup configuration state, but cannot prove the certificate currently served, revocation, backup transfer/retention/integrity/recovery, active subscription/licensing state, runtime inspection, installed effective policy, negotiated VPN security associations, peer identity, or whether a software release is currently supported.
